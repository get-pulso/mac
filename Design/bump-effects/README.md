# Bump effects: normal app integration

Реакции подключены к обычному подписанному Firstlight: реальный POST, серверный cooldown, входящие через API. Отдельный preview/playground удалён: используются настоящее окно, профиль и список друзей.

## Поведение

- **Кнопка:** floating glass capsule справа снизу, как Invite. Размер шрифта и высота совпадают с Back/Edit/Remove. Ширины Bump / Next bump in 59m измеряются заранее. Во время cooldown нет галочки, внутри кнопки показан обратный отсчёт; для дневного лимита используются часы. Нет подписи слева, полосы подвала, недельного счётчика или раздела уведомлений.
- **Отправка:** выбор одной из четырёх реакций сразу запускает свет, движение и haptics. Эмодзи декодируются параллельно; hover подготавливает выбранную пару заранее. Сетевой POST идёт в фоне, временная квитанция не пишется на диск. Успех уточняет cooldown без повторного эффекта; ошибка убирает временный cooldown и показывает текст рядом с кнопкой. Кнопка отсутствует у себя и у не-друзей; участники общей группы допустимы по действующему API. Контекстное меню списка остаётся быстрым входом.
- **Cooldown:** GET `/api/friends/[id]/bump` возвращает последний app-бамп и deadline; локальная квитанция сохраняет его между запусками. При 429 сохраняется deadline и кнопка отключается; остаток показан внутри кнопки и доступен в tooltip. Ошибка сети остаётся около кнопки. Это соответствует последнему решению убрать видимую подпись cooldown.
- **Входящий:** над текущим списком появляется лицо отправителя, имя и фраза. Каждая сцена длится 4,2 с; очередь играет по одной. Escape и круглая × переходят к следующей. Закрытие поповера отменяет текущую анимацию, ещё не показанные события сохраняются до следующего открытия.
- **Доставка:** аккаунтный inbox записывается атомарно до ACK. Повторный GET не создаёт дубль. Непоказанные моменты не обрезаются; старые просмотренные сохранены только для открытия системного уведомления, отдельного UI истории нет.
- **Уведомления macOS:** при закрытом поповере до трёх баннеров за poll и одна сводка; при открытом только оверлей. Нажатие баннера открывает список и соответствующий момент. Разрешение запрашивается один раз за запуск при первом новом входящем. Опрос каждые 45 с, при открытии и пробуждении.
- **Тактильный отклик:** NSHapticFeedbackManager, как в welcome. Два или три коротких импульса; скрытие окна отменяет оставшиеся. Импульсы с задержкой больше 180 мс пропускаются. Физическое ощущение требует поддерживаемого трекпада.

## Временный локальный тестовый цикл

В Debug с API на localhost/127.0.0.1 отправка локальная: эффект сразу, через 10 с приходит такая же реакция с именем и аватаром выбранного человека, через 20 с снова доступна кнопка. Последняя минута cooldown показывается в секундах. Каждый адресат имеет свой таймер; несколько ответов идут обычной очередью. Закрытие поповера сохраняет ожидающий ответ в памяти, а выход из аккаунта отменяет его. Тестовые квитанции и входящие отделены от постоянного inbox и исчезают при перезапуске. Нет POST, ACK или записи в чужой inbox для этих событий.

В тестовом tray есть подпись `Local test · reply in 10s · next bump in 20s`. Флаг `--live-bumps` возвращает настоящую отправку и серверные лимиты. В Release и при удалённом API этот тестовый режим всегда выключен.

## Плавность и четыре реакции

Старые WebP содержали около 15 кадров/с. Новые WebP подготовлены из оригинальных векторных TGS Telegram на **60 кадров/с**, с длительностями кадров 16/17 мс. Thumb содержит исходную неподвижную паузу: WebP объединяет одинаковые кадры, сохраняя длительность. Интерполяция старых растровых кадров не используется.

| Реакция | Разлёт | Свет и движение |
| --- | --- | --- |
| Good job | Большой палец и хлопающие ладони | Короткая золотая волна от капсулы и толчок портрета |
| On fire | Огонь и объёмные звёзды | Тёплый отблеск по стеклу |
| Keep going | Сильная рука и звёзды | Голубой восходящий свет и подъём портрета сохранены |
| Touch grass | Ростки и листья | Покачивание и зелёный отблеск |

Девять объектов, своя фаза у каждого, глубина через размер, перспективный поворот и тень. Исходящие измеряют реальный центр кнопки. Входящие разложены вокруг лица и подписи. Декодирование вне главного потока; сохраняются только две активные анимации, максимум 35,2 MiB. Таймлайны и Metal останавливаются в покое. Обычная скорость воспроизведения без замедления.

Исходники, ревизия и преобразование: [SOURCES.md](../../App/Resources/BumpEmoji/SOURCES.md). Ресурсы BumpEmoji включены во все конфигурации; новой зависимости плеера нет. Происхождение и ограничения для распространения записаны в SOURCES.md.

## Почему именно такая реализация

Свет рисует прозрачный `MTKView` поверх профиля, без перехвата мыши. Металл не растягивает текст и системные glass-кнопки. Портрет и карточка двигаются как обычные SwiftUI views. Apple предупреждает, что `layerEffect` может заменить AppKit-backed views заглушкой, поэтому фильтрация всей нативной иерархии здесь не используется: [документация layerEffect](https://developer.apple.com/documentation/swiftui/view/layereffect(_:maxsampleoffset:isenabled:)).

Metal-компиляция выполняется во время запуска, как в существующем onboarding. Дополнительный Metal Toolchain не нужен. После завершения `MTKView` очищается и переходит на обновления по событию; [описание enableSetNeedsDisplay у Apple](https://developer.apple.com/documentation/metalkit/mtkview/enablesetneedsdisplay).

Reduce Motion: неподвижное мягкое изменение света и один статичный эмодзи за 1,2 с. Один тактильный акцент, без серии. Без перелёта, деформации, тряски, частиц и движущихся теней. Системный Reduce Motion учитывается. Escape, закрытие панели и новый выбор прерывают эффект. Отложенный старт отменяется вместе с эффектом.

## Запуск

Обычное приложение с временным локальным тестовым циклом:

```sh
cd mac
FIRSTLIGHT_SKIP_SWIFTFORMAT=YES ./Scripts/run-local-signed.sh --show-dashboard
```

Настоящая отправка с серверным cooldown: тот же запуск с `--live-bumps`.
Отдельного окна preview, демонстрационных друзей и `--preview-bumps` больше нет.
